# 可嵌入应用的脚本语言与执行引擎

版本：2026-09-10-v1。状态：已选定产品方向，尚未建立实现基线。本文描述产品需求和演进边界，不表示任何能力已经实现。

## 产品目标

提供一个可被宿主应用作为库调用的脚本执行引擎。应用可以加载和编译脚本，传入结构化数据及显式注册的函数，获取结果或可定位的错误，并限制执行资源。核心功能在普通开发机上离线运行和验证。

典型用途是让应用通过脚本表达可扩展的转换与校验逻辑。例如，应用传入一组结构化对象，脚本调用应用注册的函数并返回新对象。此场景是设计用例，不代表已经存在真实部署、客户反馈或线上事故。

长期交付物包括语言规范、嵌入式调用接口、解析与编译实现、执行运行时、模块加载能力、宿主互操作、资源限制、诊断和兼容性测试。每个版本明确其支持范围，尚未支持的行为给出明确错误。

## 范围与边界

- 核心交付是软件库及其可验证行为；前端和外部服务不是前置条件。
- 不建设通用命令行产品、代码片段管理器、文件管理或同步工具、业务 CRUD 后台、报表和看板。
- 不依赖真实设备、商业账号、联网模型服务或专用硬件。
- 首期不追求完整兼容 JavaScript、Python 或其他现成语言，也不承诺原生机器码编译、JIT、分布式执行或跨平台安全沙箱。
- 宿主函数只通过显式注册暴露。语言默认不提供任意文件、网络或进程访问。资源预算属于运行控制，不能据此宣称已经建立操作系统级安全隔离。
- 实现语言、工具链版本及测试命令在首个业务基线确定，后续沿用该基线；不能把某一技术栈已经安装或已有实现当作事实。

## 必须先建立的语义契约

首个可运行版本需要明确有限语法、值类型、求值顺序、变量可见性、错误表示和公共调用方式，并提供能运行的示例。可以先实现有限范围，但同一版本不能以未说明的实现习惯替代规范。

语义需明确区分：空值与缺失名称，值相等与对象身份，编译错误与执行错误，脚本错误与宿主调用错误。数值范围、溢出、字符串索引、集合修改、参数绑定等在相应能力引入时写出可检查的约定。

先提出目标行为和验收结果，再根据已有代码确定实现路线。函数名、目录结构、错误码或内部算法尚未存在时，不把示意设计写成已有接口。

## 能力地图

以下是长期演进方向。实际版本按依赖选择有限目标，不要求首个版本全部具备。

| 领域 | 要解决的问题 | 验收依据 |
|---|---|---|
| 词法与解析 | 字符串、运算符、嵌套结构、源码定位、错误恢复 | 指定源码对应的语法结构或错误位置 |
| 值与集合 | 数值边界、转换、相等性、可变性、集合迭代 | 明确的返回值、状态变化和错误 |
| 名称与作用域 | 遮蔽、未绑定名称、闭包捕获、变量生命周期 | 含嵌套作用域的程序及其结果 |
| 函数调用 | 参数绑定、递归、返回值、调用栈 | 调用结果、失败条件和堆栈信息 |
| 编译与执行 | 控制流、短路求值、字节码或其他执行表示 | 规范示例、执行顺序与结果一致性 |
| 模块 | 导入解析、循环依赖、失败清理、模块缓存 | 加载顺序、可见导出和失败后状态 |
| 宿主互操作 | 函数注册、数据转换、异常传播、对象持有 | 库接口契约和可控宿主测试程序 |
| 资源与生命周期 | 执行预算、取消、嵌套限制、实例清理 | 可控输入下的终止行为和资源释放 |
| 诊断与调试 | 源码映射、调用位置、错误上下文 | 可重复的错误位置与诊断结构 |
| 性能与复用 | 编译缓存、运行实例复用、内存分配和执行优化 | 行为等价及注明环境的性能测量 |
| 兼容与演进 | 规范版本、公共 API、编译产物格式 | 固定版本用例的兼容结果 |

## 演进顺序

1. **最小完整链路**：固定有限语义，宿主通过库接口传入源码和数据，完成解析、执行及错误返回。建立可重复运行的示例和验证命令。
2. **语言组合能力**：在已实现语义上扩展控制流、函数、作用域和集合；每次扩展核对与已有行为的组合关系。
3. **应用嵌入能力**：完善模块、宿主函数、数据交换、取消和资源生命周期，形成可运行的集成用例。
4. **执行与兼容演进**：有实际需求和测量依据后，引入执行优化、编译缓存、版本兼容与诊断增强。

每个版本的具体范围由当时的仓库状态和明确需求决定；已有能力不足时先处理其真实依赖，不能假设未来代码已经存在。

## 验收原则

- 核心验证必须能在本地重复执行，输入、预期结果和错误条件可读、可检查。
- 测试数据和示例程序明确属于测试，不冒充真实用户事故或生产数据。
- 可使用参考实现做差异检查，但只比较双方明确承诺一致的语义；参考实现的行为不自动成为本项目规范。
- 性能结论记录运行环境、输入规模和比较基线。正确性尚未满足时，不能用速度改善替代正确性验收。
- 需求文档、已实现能力和待规划能力分别说明。新增功能有明确完成条件，完成后再选择下一项产品目标。
